## Beacon: security alerts for Solana validator operators

[Beacon](https://www.solyrae.com/beacon.html) is a free security bulletin for everyone who runs a Solana validator. It collects vulnerabilities and security releases for everything a validator runs on, ranks them and tells operators what they affect and what to do.

**Components covered:** Agave, Jito, Firedancer, the Rust crates inside the clients, the Linux kernel, Ubuntu, Debian, OpenSSL, OpenSSH, systemd and Docker.

**How it works** (`tools/build_beacon.py`, run every 3 hours by `.github/workflows/beacon.yml`):

1. **Reads public sources:** GitHub releases of Agave, Jito and Firedancer; the minimum version required by the Solana Foundation Delegation Program (Vortex); Ubuntu security notices; Debian security advisories; the CISA Known Exploited Vulnerabilities catalog; security posts on the Anza blog.
2. **Checks the real software:** downloads the exact `Cargo.lock` of the latest Agave and Jito releases and queries [OSV](https://osv.dev) for every crate, so operators see which known advisories ship inside the client they run.
3. **Ranks every alert:** Critical (known to be exploited), High, Watch or Info, combining the CVSS score (NVD), the CISA KEV list and the FIRST EPSS exploit probability. No one edits the alerts by hand.
4. **Publishes:** `site/data/beacon.json` for the page, one Atom feed per component (`site/feeds/beacon-<component>.atom`), an all-alerts Atom feed and a JSON Feed.
5. **Emails a daily digest** (`tools/beacon_email.py`): subscribers choose their components on the page and confirm by email (double opt-in, through Brevo); once a day each list gets the new Critical, High and Watch alerts for its component, only when there is something new.

**Limits.** Beacon shows what is already public. Serious client flaws are handled privately until a fix is ready, and Anza warns validators through its own channel; Beacon complements that channel and does not replace it. It is a community service by SoLyrae, not an official Solana, Anza, Jito or Firedancer channel.

## The rest of the website

- **Explorer:** every Solana validator with stake, with live performance, commission and location data (Stakewiz) and epoch history (Vortex).
- **Decentralization:** stake concentration by validator, hosting provider, country and client, with Nakamoto coefficients.
- **Performance, rewards and infrastructure** of the SoLyrae validator, from public data.
- **Tools:** rewards calculator and side-by-side validator comparison.
- **Blog:** plain-language guides for delegators and operators.

## Repository layout

| Path | What it is |
|---|---|
| `site/` | The static website (HTML, CSS, vanilla JavaScript), published with Cloudflare Pages |
| `site/data/`, `site/feeds/` | Generated by the workflows; do not edit by hand |
| `functions/api/subscribe.js` | Cloudflare Pages Function for the Beacon email sign-up |
| `tools/build_beacon.py` | Beacon collector (Python standard library only) |
| `tools/beacon_email.py` | Email designs and daily digest sender |
| `tools/setup_brevo.py` | One-time setup of the Brevo lists and confirmation template |
| `tools/build_network_rewards.py` | Network rewards history, run by `.github/workflows/rewards.yml` |
| `tools/make_*.py` | Image generators (share card, logos, social posts) |

Keys (`NVD_API_KEY`, `BREVO_API_KEY`) are read from environment variables: GitHub Actions secrets and Cloudflare settings. None are stored in this repository.

## Run Beacon locally

```bash
python tools/build_beacon.py
```

Python 3.10+ with no extra packages. An NVD API key is optional and only adds CVSS scores. Local runs never send emails.

## Data sources

Stakewiz, Vortex (vx.tools), OSV, RustSec, GitHub, Ubuntu, Debian, CISA, FIRST, NVD and DB-IP. Figures can be delayed or differ slightly between sources; see [How we measure](https://www.solyrae.com/methodology.html).
