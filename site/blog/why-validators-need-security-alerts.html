Why Solana validators need security alerts: lessons from past patches

Network · 14 Nov 2026 · SoLyrae

Security fixes for validators arrive on short notice and expect a quick response. Anza, the team behind the Agave client, has published root cause analyses of several incidents. They show the pattern well.

August 2024: a flaw that could halt the network

On 5 August 2024 Anza engineers learned of a vulnerability, reported by an external researcher, that affected the Agave and Jito clients. It would have allowed an attacker to crash leaders one by one, eventually halting the network. Anza prepared a patch, had it audited by several outside firms and worked with operators to apply it. By 8 August, over 67% of the network had applied the patch, which made consensus safe from that disruption. Anza's write-up adds that infrastructure that had not been patched could still be at risk.

December 2024: a library that was compromised

Compromised versions of @solana/web3.js, a widely used JavaScript library, reached the npm registry. Anza's analysis explains how it happened, who was affected and what changed afterward. It is a reminder that the risk is not only in the validator client: it is also in the packages and tools around it.

April 2025: a bug exposed by an option

A bug in how Agave implemented two signature-check programs, ed25519 and secp256r1, surfaced for validators that ran a new option introduced in version 2.2. Anza's root cause analysis shows that a flaw can affect only some configurations, so operators need to know what their own setup uses.

January 2026: two critical potential vulnerabilities

Two critical potential vulnerabilities were reported to Anza through GitHub security advisories in December 2025. One was an attack on the gossip protocol that could crash a node, and the other a potential attack to censor votes. They were patched in collaboration with Firedancer, Jito and the Solana Foundation. Anza recommended upgrading to Agave and Jito 3.0.14, or Frankendancer 0.808.30014, and said no attack on the cluster was known. Read the patch summary.

What these cases teach

  • The window is short. In August 2024 it took about three days to reach two thirds of the network.
  • Serious flaws are handled privately first. Operators usually hear about them only when a fix is ready, so a missed message can mean running vulnerable software.
  • The risk is wider than the client. It includes libraries, the operating system and the tools used to run the node.
  • Knowing what you run matters. Some flaws only affect certain versions or options.
