A security checklist for Solana validator operators

Guide · Nov 14, 2026 · SoLyrae

This is a practical checklist built on common good practice for servers that run validators. It is not an official guide. For the details of running a validator, use Anza's operations documentation.

1. Software

  • Run a current release of your client, and stay at or above the minimum version your delegation program requires.
  • Have a written routine for upgrades, and know how quickly you can apply an urgent one.
  • Know which version and options you run, because some fixes only affect certain setups.

2. Operating system

  • Install security updates for the kernel and for packages such as OpenSSL, OpenSSH and systemd, and reboot when a kernel update needs it.
  • Run only what the server needs. Fewer services mean fewer ways in.
  • Keep the same attention for every operating system you use, whether Ubuntu or Debian.

3. Access

  • Log in with keys, not passwords, and do not allow direct root login.
  • Limit who can reach the server, and from which addresses, with a firewall.
  • Give each person their own account, and remove access as soon as someone leaves.

4. Keys

  • Keep the withdraw authority of the vote account off the validator server. A multisig adds protection, because no single key can move it.
  • Keep on the server only what the validator needs to vote, and hold no more funds there than it needs.
  • Back up keys offline, and test that you can restore them.

5. Monitoring

  • Watch that the validator is voting, not delinquent and not falling behind, and get an alert when it is.
  • Watch the balance of the vote account, because the fixed per-epoch fee under Alpenglow has to be covered.
  • Follow security alerts for the components you run. Beacon lets you pick them and subscribe.

6. Resilience

  • Have a backup server that can take over if the main one fails, and practise the switch.
  • Know how to contact your hosting provider quickly.
  • Write down what you do in an emergency, so that it does not depend on one person's memory.
